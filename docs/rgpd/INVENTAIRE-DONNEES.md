## Lecture et périmètre

- **A — FAIT TECHNIQUE VÉRIFIÉ** : observation du code, des migrations ou d'une exécution identifiée. Les tableaux techniques ci-dessous relèvent de A, sauf mention contraire.
- **B — INFORMATION DOCUMENTAIRE VÉRIFIÉE** : documentation officielle datée ; références dans [Flux et prestataires](FLUX-ET-PRESTATAIRES.md).
- **C — RECOMMANDATION** : proposition non appliquée, notamment dans [Préparation des droits](PREPARATION-DROITS.md).
- **D — DÉCISION À VALIDER** : choix/information manquant à l'exploitant, suivi dans [Décisions](DECISIONS-A-VALIDER.md).

Le défaut [auth-config.json](../../assets/auth-config.json) contient `enabled:false`, URL et clé vides. Le visiteur utilise les stockages de l'appareil. Auth et synchronisation personnelles sont développées pour un environnement configuré, sans ouverture publique étudiante démontrée ici. Aucun export global, suppression de compte ou purge RGPD n'est livré. Les données pédagogiques liées à un UUID sont personnelles ; un UUID n'est pas une anonymisation. Sans compte, la sauvegarde peut aussi concerner une personne identifiable dans son contexte, notamment sur un appareil partagé.

Les inventaires utilisent les identifiants ci-dessous pour relier flux, registre et droits. Les noms de clés sont des **patrons**, jamais des valeurs réelles. Aucun token, e-mail personnel ou identifiant étudiant n'est reproduit.

## Règles communes de lecture, accès et durée

| Code utilisé dans les tableaux | Accès, protection, exportabilité et suppression futurs |
| --- | --- |
| L — local visiteur | Lecture/écriture par l'application dans le profil navigateur de même origine ; aucune authentification locale. Accessible à qui contrôle ce profil, aux scripts de même origine et aux extensions autorisées. Pas de chiffrement applicatif observé. Export envisageable après attribution explicite à la personne ; suppression sélective future, jamais assimilation automatique au compte connecté. |
| P — cache personnel | IndexedDB, version 1, store `accounts`, clé `JSON.stringify([environment, origineSupabase, UUIDAuth])`. Une transaction `get`/validation/`put` attend `transaction.oncomplete`. Sélection par identité/génération, pas par e-mail. Même exposition locale que L : le cloisonnement applicatif n'est pas un chiffrement ni une barrière contre le propriétaire du profil. Export futur de la seule portée vérifiée, avec provenance et état local/distant ; purge future par portée, sans toucher B lors d'une demande A. |
| S — SQL applicatif | `public`, lecture PostgREST et écritures RPC authentifiées ; RLS par `auth.uid()`, grants de colonnes, contraintes et triggers. Pas de DELETE étudiant accordé. Export futur sous identité vérifiée, toutes pages et données locales complémentaires ; suppression via une procédure de confiance à concevoir. Administrateurs PostgreSQL et opérateurs habilités peuvent avoir des accès privilégiés ; habilitations réelles non vérifiées. |
| H — Auth/prestataire | Auth API et stockage interne du fournisseur ; pas de SELECT étudiant sur le schéma `auth` depuis le client applicatif. Accès administratif et rétention à vérifier avec le prestataire. Export via une procédure de confiance minimisée, jamais avec mot de passe, JWT, refresh token ou secret de lien. Suppression/révocation et copies fournisseur à traiter séparément. |
| M — mémoire/communication | État transitoire, pas de stockage durable ajouté par ce mécanisme ; le navigateur, l'OS ou des journaux peuvent laisser des copies hors contrôle du code. Ne pas exporter un secret de session. |

**Durée fonctionnelle par défaut : aucune échéance temporelle d'effacement applicatif observée pour L/P/S.** Une donnée reste tant qu'elle n'est pas remplacée selon les règles métier, retirée par une action technique extérieure, ou perdue/évincée par le navigateur. Ce constat n'autorise pas une conservation indéfinie. Déconnexion : vues et requêtes invalidées, historique et outbox conservés. Exceptions de bornes en nombre et données transitoires précisées plus bas. **D : aucune politique de durée validée n'est fournie.** Une cascade SQL est une capacité relationnelle, pas une suppression actuellement proposée à l'étudiant.

## Bilan de conservation et complétude

### Delta 6.4.3 (les tableaux ci-dessus décrivent l'audit initial)

Le [lot 6.4.3](../architecture/SUPPRESSION-DONNEES-PERSONNELLES.md) ajoute l'effacement local sélectionné et un prototype de clôture strictement éphémère. Les quatre bases conservent leurs noms et records `accounts` v1 ; leur **version de base** passe à 2 avec `privacy[scope] = {version:1,epoch,blocked}`. La portée UUID reste personnelle : ce marqueur n'est ni anonyme ni un historique pédagogique ; il demeure après retrait/reprise pour bloquer les anciens clients. Durée nécessaire et retrait futur à valider D07/D08/D12/D13, sans TTL ni suppression aveugle de comptes. L'export pédagogique 6.4.2 reste partiel et n'en prétend pas la couverture.

Le canal `mon-bprea-privacy-v1` transporte seulement `{phase:'suspend'|'settled'}`, sans UUID, réponses ou token. Web Locks coordonne les actions destructives locales. Le serveur local reçoit temporairement Bearer/mot de passe pour une nouvelle connexion native puis une capacité chiffrée d'autorisation en mémoire ; aucune copie de ces secrets dans les caches, exports ou logs applicatifs, aucun dossier nominatif serveur ajouté. Les logs d'infrastructure restent un traitement fournisseur à qualifier. Aucun usage Storage ajouté et aucun service déployé sur DEV/PROD. [Projet de conservation](POLITIQUE-CONSERVATION-PROJET.md) non validé, aucune purge automatique ; [preuves et limites](../validations/VALIDATION-LOT6-4-3.md).
